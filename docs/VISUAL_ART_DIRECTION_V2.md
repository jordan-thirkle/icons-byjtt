# JTT Icons — Visual Art Direction v2

## Canonical visual contract

JTT Icons remains a 24×24 line family designed for interface-scale clarity.

- 2px optical stroke
- round caps and joins
- currentColor
- no decorative fills for non-brand icons
- geometry stays inside a consistent visual field
- distinctive silhouettes at 16px and above
- avoid unnecessary interior detail
- semantic meaning must survive monochrome rendering
- brand marks are the explicit filled exception

## Art-direction review set

The highest-frequency concepts remain the visual anchors: search, home, upload, download, delete, edit, copy, settings, user, users, message, mail, heart, star, check, x, chevrons, arrows, folder, file, calendar, clock, lock, eye, filter, play, pause, volume, code, terminal, database and server.

These are treated as the reference shapes for future additions. New icons should match their stroke weight, corner language, negative-space discipline and 16px readability rather than independently inventing a style.

## Catalogue v2

The 300-icon release expands semantic coverage across actions, navigation, communication, media, files, objects, people, commerce, developer tooling, system states and brands.

AI-native concepts are explicitly represented:

- ai-agent
- ai-model
- ai-prompt
- ai-generate
- ai-chat
- ai-search
- ai-code

These are not cosmetic aliases: they participate in the same ontology and relationship graph as ordinary interface concepts.

## Review gate for future icons

Before an icon is accepted:

1. Is the concept already represented by an existing canonical icon?
2. Is the silhouette recognisable at 16px?
3. Does it remain balanced at 24px?
4. Does it use the family stroke contract?
5. Does its metadata express intent, context and useful relationships?
6. Can an AI agent retrieve it from natural language without guessing?
7. Does it have a stable implementation path?
